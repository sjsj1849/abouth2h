# About H2H · 同人作品索引与 Weverse 数据报表

**站点：[abouth2h.com](https://abouth2h.com)**

About H2H 包含两部分：一部分把 AsianFanFics（亚网）和 Postype（破塔）上的 Hearts2Hearts 同人作品整理成可搜索、可筛选、可看趋势的索引；另一部分把成员在 Weverse 的帖子、回复、直播与互动数据整理成周期报表。

这个仓库只放**说明文档**，不放站点源码，也不放任何作品正文。想看站点直接点上面的链接就行。

---

## 这是什么

- **是索引，不是转载站**：只记录标题、作者、简介摘要、属性标签、原站链接，以及原站公开显示的浏览 / 点赞 / 评论数字。
- **不镜像正文**，不提供下载，不绕过任何登录、订阅、付费或翻译积分。
- **非官方**，与艺人、经纪公司及官方没有任何关系。作品版权归原作者所有。

做它的原因挺简单：自己想找文的时候，各处的标签散得很，就顺手整理成一个能搜、能看排行的地方。后来又把成员在 Weverse 的发帖、评论、直播数据做成了报表，原本也是做给自己看的，既然都做出来了，就一起放在这儿。

## 站点能做什么

| 入口 | 做什么 |
| --- | --- |
| **找文** | 按成员、CP、左右位、无差、NP、梦向、三角筛选。选 1 位看成员的文，选 2 位看这对 CP，选 3 位看三角 |
| **作品排行** | 按浏览 / 点赞（亚网是订阅）/ 评论三项名次相加排序，越小越靠前 |
| **合并榜** | 把一对 CP 的左右位合并成总榜；也可以展开看左 / 无差 / 右各占多少 |
| **成员分布** | 每位成员的作品在左右位上的分布，可忽略无差 / 特殊后再算 |
| **增长趋势** | 看在某个时间窗口里，各 CP 新增了多少。三种视角（趋势图 / 明细表 / 增长排行）共用一套组合筛选，另可切「全部组合」「全部方向」 |
| **特殊** | 三角、NP、梦女这类非双人向的作品 |
| **查收录** | 贴作品链接或输标题片段，先确认站里有没有收，再决定要不要提遗漏 |
| **反馈** | 属性有误 / 不该收录 / 遗漏作品 / 其他。每篇作品旁边就有「✎ 属性有误」「⚑ 不该收录」的快捷入口，会**自动带上作品编号和标题** |
| **Weverse 数据中心** | 成员的帖子、回复、直播、弹幕、互动数据，支持周报 / 月报 / 半年报 / 年报 |

## Weverse 报表

Weverse 报表不是同人作品索引的附属统计，而是站点的另一项独立功能。它使用已经采集的公开动态记录，在打开页面时按所选周期实时聚合：

- 支持周报、月报、半年报和年报；
- 汇总成员发帖、Moment、回复、直播和直播弹幕等公开活动；
- 展示成员活跃度、互动对象与互动趋势；
- 可以切换成员和统计周期，查看相同口径下的明细；
- 与内部群报表使用同一套数据口径，但公开站只展示适合公开查看的聚合结果。

报表并不代表成员关系或官方结论，只是对公开事件记录的结构化整理。由于网络、删除内容、平台接口变化和采集时间差，数字可能与 Weverse 页面当下显示的结果存在少量差异。

## 现在有多少

作品数字每天都在变，这里只是某一时刻的快照：

- 两个平台合计约 **6,100 篇**（AsianFanFics 2,308 篇 · Postype 3,811 篇）
- Postype 有 **305 组连载**按「同一专栏 + 标题基本相同」合并成了一篇，避免同一篇长文被拆成几十条重复作品
- **25 对 CP**
- 数据更新：AsianFanFics **每 24 小时**、Postype **每 12 小时**；Weverse 报表是**打开时实时聚合**，不是定时批处理

## 属性怎么写

站内所有属性都用**纯数字**，左在前、右在后。

**成员编号**

| 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Carmen | Jiwoo | Yuha | Stella | Juun | A-na | Ian | Ye-on |

**写法**

| 写法 | 含义 |
| --- | --- |
| `47` | 4 在左、7 在右 |
| `74` | 反过来，7 在左、4 在右 |
| `47无差` | 分不出左右 |
| `23/47` | 一篇文里有两对 CP，各自左在前 |
| `25无差/36/47` | 多对，其中有对有差 |
| `346` | 三角，三位成员 |
| `all7` | NP，中心是 7 |
| `梦4` | 梦女向，对象是 4 |

判定顺序是：**标签决定这篇文属于谁，简介里的数字只用来决定谁在左**。所以一篇标签明确写着某一对 CP 的文，不会因为简介里恰好出现三个数字就被判成三角。

## 数据从哪来

- 两个平台**公开可见**的作品信息（标题、标签、简介、公开热度数字）。不登录他人账号，不读取付费内容。
- 连载合并只在**同一专栏且标题主干相同**时生效——有的作者拿专栏当分类放不同短篇，这些不会被合并。
- 中文标题优先用 **Postype 自带的中文版本**（站点切到简体中文时返回的那份），没有官方译文时用机器翻译兜底，所以冷门作品可能还是韩文原名。

## 已知限制

说在前面，免得你以为是 bug：

- **属性会被判错**。标签缺失、简介写法千奇百怪，机器判定不可能全对。看到不对，点作品旁边的「✎ 属性有误」告诉我就行。
- **冷门作品可能没有中文标题**，只有韩文原名。
- **站方不公开的数据不会伪造**。没有收藏数就不显示收藏数，不会拿别的数字凑。
- **增长趋势依赖历史快照**。某天没采到就是没采到，不会用插值补出来。
- 索引有延迟：新发的文最长要等一个更新周期才会出现。

## 反馈

两种方式，随便挑：

1. **站内提交**（最快）：作品旁边直接点「✎ 属性有误」或「⚑ 不该收录」，编号和标题已经填好，你只要写建议属性和一句依据。**不需要留任何联系方式**。
2. **[GitHub Issues](../../issues)**：适合要贴多张截图、或者问题比较复杂的情况。提之前建议先去站内「查收录」确认这篇到底有没有被收录。

所有提交都进同一个待审核队列，**不会立即生效**，核实后才会更新公开数据。

## 相关项目

### Luma Reader / Luma H2H

**[github.com/sjsj1849/Luma-Reader](https://github.com/sjsj1849/Luma-Reader)**

一个面向 Android 的轻量多站点小说阅读器，把 AsianFanfics、PO18、海棠文学城和 Postype 放进同一套搜索、书架和阅读界面里。同样不镜像内容，登录和付费都留在原站完成。

它的 **[Releases](https://github.com/sjsj1849/Luma-Reader/releases/latest)** 里有两个安装包：

- **Luma Reader**：通用版；
- **Luma H2H**（文件名带 `-H2H`）：在通用版基础上接入了本站的「亚网找文」——可以按成员、CP、左右位、无差、NP、梦向、三角筛选，直接在阅读器里打开作品，也能提交属性纠错。它用独立包名，可以和通用版同时安装。

这个版本只读本站的公开数据，不包含任何后台地址、会话或写入权限。手机上找文、看文一条龙的话，用它比来回切浏览器舒服。
